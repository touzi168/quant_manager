# 量化可视化和监控系统设计文档

## 1. 项目概述

### 1.1 项目背景
本项目旨在构建一个完整的量化交易可视化和监控系统，通过Web界面展示和管理量化策略的运行情况，包括资产监控、持仓分析、资金曲线、服务器健康状态等功能。

### 1.2 项目目标
- 提供直观的数据可视化界面
- 实现用户权限管理和数据隔离
- 实时监控系统健康状态
- 支持策略级别的数据分析和展示

## 2. 系统架构设计

### 2.1 整体架构

```
前端层:
├── Web前端应用 (React/Vue)
└── 移动端应用

应用层:
├── 认证服务 (用户认证、权限验证)
├── API网关 (请求路由、限流)
├── 核心业务服务 (数据聚合、业务逻辑)
└── 实时数据服务 (WebSocket、推送)

数据层:
├── MariaDB主数据库 (用户数据、系统配置 + 交易数据)
└── Redis缓存 (会话、热点数据)

外部服务:
├── Google Authenticator (二次认证)
└── 邮件服务 (通知、验证码)

数据流向:
前端 → API网关 → 认证服务 → 核心业务服务 → 本地MariaDB
                                        ↓
                                  数据聚合服务
                                        ↓
                                  Redis缓存层
```

架构说明:
- 采用分层架构，各层职责清晰
- 前端层负责用户界面展示
- 应用层处理业务逻辑和认证授权
- 数据层负责数据存储和缓存
- 外部服务提供额外的功能支持
    RealTime --> TimeSeries
    Auth --> 2FA
    Core --> Email
    Core --> RemoteDB
```

### 2.2 技术栈选型

#### 后端技术栈
- **框架**: Node.js + Express.js / Python + FastAPI
- **数据库**: 
  - 主数据库: MariaDB (用户数据、系统配置 + 远程交易数据)
  - 缓存: Redis
- **认证**: JWT + Google Authenticator
- **任务调度**: Node-cron / Celery
- **API文档**: Swagger/OpenAPI

#### 前端技术栈
- **框架**: React 18 / Vue 3
- **状态管理**: Redux Toolkit / Vuex 4
- **UI组件库**: Ant Design / Element Plus
- **图表库**: ECharts / Chart.js
- **构建工具**: Vite / Webpack

## 4. 用户认证和权限管理设计

### 4.1 认证流程

```
用户认证流程步骤:
1. 用户提交登录请求
   ├── 发送邮箱和密码到API网关
   
2. API网关处理请求
   ├── 验证请求格式
   ├── 转发到认证服务
   
3. 认证服务验证用户凭据
   ├── 查询数据库中的用户信息
   ├── 验证密码哈希是否匹配
   
4. 密码验证结果判断
   ├── 密码错误 → 返回错误信息
   └── 密码正确 → 继续下一步
   
5. Google认证状态检查
   ├── 检查用户是否启用了2FA
   ├── 未启用 → 直接创建会话
   └── 已启用 → 要求输入验证码
   
6. Google验证码验证
   ├── 用户输入6位验证码
   ├── 服务验证验证码有效性
   ├── 验证失败 → 返回错误
   └── 验证成功 → 创建用户会话
   
7. 会话创建和Token生成
   ├── 在数据库中创建会话记录
   ├── 生成JWT Token
   ├── 返回Token给用户
   └── 完成认证流程
```

#### 7.3.2 资金曲线查询服务

```javascript
// 资金曲线查询服务
const EquityCurveService = {
    // 获取资金曲线数据
    async getEquityCurve(email, strategyId, timeRange) {
        const config = DataAggregation.equityCurve;
        const rangeConfig = config.timeRanges.find(r => r.value === timeRange);
        
        if (!rangeConfig) {
            throw new Error('Invalid time range');
        }
        
        // 检查缓存
        const cacheKey = `equity_${email}_${strategyId}_${timeRange}`;
        const cachedData = await redis.get(cacheKey);
        
        if (cachedData) {
            return JSON.parse(cachedData);
        }
        
        let query;
        
        // 根据时间范围选择查询策略
        if (timeRange === '7d') {
            // 短期：直接查询原始数据
            query = this.getRawDataQuery(email, strategyId, timeRange);
        } else {
            // 长期：查询重采样数据
            query = this.getResampledDataQuery(email, strategyId, timeRange);
        }
        
        const data = await this.executeQuery(query);
        
        // 缓存结果
        await redis.setex(cacheKey, 1800, JSON.stringify(data)); // 30分钟缓存
        
        return data;
    },
    
    // 原始数据查询（短期）
    getRawDataQuery(email, strategyId, timeRange) {
        return `
            SELECT 
                time,
                net_realized,
                net_unrealized
            FROM equity 
            WHERE email = ?
                AND time >= DATE_SUB(NOW(), INTERVAL ${timeRange.replace('d', ' DAY')})
            ORDER BY time ASC
        `;
    },
    
    // 重采样数据查询（长期）
    getResampledDataQuery(email, strategyId, timeRange) {
        return `
            SELECT 
                DATE_FORMAT(time, '%Y-%m-%d %H:00:00') as hour_time,
                AVG(net_realized) as net_realized,
                AVG(net_unrealized) as net_unrealized
            FROM equity 
            WHERE email = ?
                AND time >= DATE_SUB(NOW(), INTERVAL ${timeRange.replace('d', ' DAY')})
            GROUP BY hour_time
            ORDER BY hour_time ASC
        `;
    }
};

WORKDIR /app

COPY package*.json ./
RUN npm ci --only=production

COPY . .

EXPOSE 3000

CMD ["npm", "start"]
```

#### 8.2.2 Docker Compose配置

```yaml
# docker-compose.yml
version: '3.8'

services:
  web-app:
    build: .
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - DB_HOST=mariadb
      - REDIS_HOST=redis
    depends_on:
      - mariadb
      - redis
    volumes:
      - ./logs:/app/logs

  mariadb:
    image: mariadb:10.8
    environment:
      MYSQL_ROOT_PASSWORD: rootpassword
      MYSQL_DATABASE: quant_monitor
    volumes:
      - mariadb_data:/var/lib/mysql
    ports:
      - "3306:3306"

  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
    volumes:
      - redis_data:/data

  influxdb:
    image: influxdb:2.0
    ports:
      - "8086:8086"
    environment:
      DOCKER_INFLUXDB_INIT_MODE: setup
      DOCKER_INFLUXDB_INIT_USERNAME: admin
      DOCKER_INFLUXDB_INIT_PASSWORD: password123

volumes:
  mariadb_data:
  redis_data:
```
